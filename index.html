Skipping the work

Picture a board game that never ends. On every square you pick a move, and each move takes you to another square and pays you some points. Since you play forever, what counts is your average score per move. From each square, what is the best average you can get?

You always end up going round some loop again and again, so the answer comes down to finding the loops with the best average. This page shows the standard way to find them, and our idea: a cheap test that proves whole parts of the board aren't worth searching.

The basics

What is an MDP?

A Markov decision process (MDP) is the standard way to describe a problem where you make one decision after another and each one changes what you can do next. It is the model underneath reinforcement learning. It has five parts:

States
Where you can be: a square on the board, a machine's settings, a robot's position.
Actions
What you can do in each state. Each one moves you to a next state.
Rewards
What each action pays, or costs if it is negative.
Policy
A rule that picks an action in every state. This is what you are trying to find.
Gain
The average reward per step a policy earns in the long run. The best one is written $g^*$.

Deterministic or random

In general an action leads to a next state at random, like a robot whose wheels sometimes slip. We study the deterministic case, where each action always leads to the same place. Then an MDP is just a graph: states are dots, actions are arrows, and every policy ends up going round a loop forever.

Average or discounted

Most reinforcement learning discounts the future: a reward next year counts for less than one today. For tasks that never stop, like running a data centre or a factory, the natural score is the long-run average instead. It needs different tools, and it's the one we use.

Learning or planning

A reinforcement-learning agent has to learn by trial and error, because it doesn't know the MDP. Planning is the other half: when the MDP is known, compute the best policy outright. Learning agents plan inside the model they have learned, so faster, exact planning helps both.

Why it matters

The same question, in many places

“Which loop has the best average?” is the maximum mean cycle problem. Solving a deterministic MDP's average reward is exactly this problem, and it turns up well beyond games:

Reinforcement learning

Agents that run for good, such as controllers and schedulers, are scored by average reward. Planners often work in a learned model that is deterministic, as MuZero's is.

Chips

In a digital circuit, the loop with the longest average delay sets how fast the clock can tick. The real-world graphs we test on are circuits.

Production and pipelines

In a production line or a program that repeats, the slowest repeating cycle caps how much gets done per hour.

Checking systems

Tools that verify software and hardware compute long-run averages, such as the share of time a system is up, on MDP models of it.

Games

Mean-payoff games, used to design systems that keep behaving well forever, are the two-player version of the same question.

Network flows

A classic way to find the cheapest flow through a network repeatedly cancels the cycle with the best mean, so it runs this problem in a loop.

The project

What we did

A skip test, proved safe Cheap upper bounds that rule out an SCC before solving it, with proofs that skipping is sound, never changes the answer, and costs no more than Karp in the worst case. A hybrid solver The cheapest test first, then Howard's method on each SCC that is left, with Karp as a safety net when Howard runs long. A C++ library dmdp: Karp, the cascade, Howard and the hybrid, all in exact fractions, with a brute-force checker and the step-by-step recordings this site plays. Seven experiments 136 graphs, from generated families to real circuits: is it exact, is it safe, when does it help, and how does it compare with Howard?
What we found

Exact, safe, and sometimes a lot less work

Skipping pays off when SCCs further along are better than the ones before them, and does nothing when they are worse. On real circuits most SCCs have no cycle at all, so there is little to skip, and Howard's method is still the one to beat there.
